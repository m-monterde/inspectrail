API: GraphQL vs REST — ADR-005

REST

  • Endpoints fijos por recurso
  • Over-fetching: campos innecesarios
  • Under-fetching: múltiples llamadas
  • Real-time: WebSocket separado
  • Los endpoints proliferan

GraphQL

  • Un endpoint, el cliente define qué pide
  • Datos exactos por cada vista
  • Una petición para datos relacionados
  • Subscriptions nativas
  • Schema tipado = contrato front↔back

Decisión: GraphQL + Node.js + TypeScript — alineado con el stack de InspectRail

Arquitectura de la API

Schema .graphql = Contrato del API (equivale a DTOs) ↓ Resolvers = Controllers (delegan a services) ↓ Services = Lógica de negocio ↓ Prisma ORM = Acceso a datos type-safe → PostgreSQL

NestJS ❌

Over-engineering para el alcance del proyecto

Schema-first ✅

Capa de servicios, separación clara

Resolvers→Prisma ❌

Mezcla lógica con resolución de datos

Seguridad

Autenticación — JWT

  • HS256, expira en 24h
  • Stateless: no sesiones en servidor
  • Passwords: bcrypt (coste 10)
  • Descartado: sesiones (requiere Redis), OAuth2 (sobredimensionado)

Autorización — RBAC

  • 5 tablas: users→roles→permissions
  • 10 permisos granulares
  • Nuevo rol = config en BD, sin tocar código
  • Descartado: check de rol directo (rígido), ABAC (overkill)

Multitenencia

  • Filtrado automático por organizationId
  • Org A nunca ve datos de Org B
  • Dispositivos: api_key + api_secret (bcrypt)

Transporte

  • HTTPS con Let's Encrypt (auto-renovación)
  • BD y API: solo red interna Docker
  • .env con secretos fuera del repo

Frontend: ¿Por qué WebGL? — ADR-008


Puntos de datoSVG / DOMWebGL / Canvas
10.000🐌 Lento✅ 60fps
100.000💀 Se congela✅ 60fps
500.000💀 Imposible✅ 60fps

SVG/DOM (Leaflet, Recharts)

Cada punto = un elemento HTML. El navegador crea, posiciona y repinta TODOS en cada frame

WebGL (MapLibre, ECharts)

Todos los puntos → GPU (tarjeta gráfica). Renderizado en paralelo. Misma tecnología que los videojuegos


Un trayecto de 50km a 10cm = 500.000 puntos. WebGL no es opcional.

Evolución y escalabilidad

Escalado de datos

  • Compresión TimescaleDB ~95%
  • Continuous aggregates
  • Downsampling en API (time_bucket)
  • Downsampling en frontend (por zoom)

Machine Learning

  • Python preparado (NumPy/SciPy/sklearn)
  • De umbrales estáticos → modelos predictivos
  • Servicio independiente: evoluciona sin tocar API

On-premise

  • Docker save → tar → hardware sin internet
  • PMTiles: mapas locales
  • Nginx reemplaza Traefik
  • Sincronización al conectar

Observabilidad
